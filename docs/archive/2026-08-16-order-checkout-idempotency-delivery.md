# ORD-002 结算请求幂等交付记录

## 交付目标

旧的 `POST /api/cart/checkout` 没有请求幂等键。用户重复点击、页面刷新、网络超时后重试，或两个后端实例同时收到同一次结算意图时，系统可能创建多张订单并重复冻结库存。

本批次为一次结算意图建立浏览器、HTTP 接口、Java 服务和 MySQL 之间的统一身份。相同用户使用相同键和相同请求内容时只产生一张订单；相同键被用于不同请求时明确拒绝；正确性由数据库约束保证，不依赖某个 Java 进程仍然存活。

## 已实现的业务规则

1. `POST /api/cart/checkout` 强制要求 `Idempotency-Key` 请求头，值必须是小写标准 UUID；缺失或格式错误返回 HTTP 400。
2. 后端先校验数量、合并重复商品、按商品 ID 排序并规范化支付宝支付方式，再计算带版本的 SHA-256 请求指纹。指纹不包含 Token、用户资料、商品标题或客户端价格。
3. 同一用户和同一键永久绑定一张订单。相同指纹重放时返回原订单，并增加 `Idempotent-Replay: true`；不同指纹返回 HTTP 409。
4. 不同用户可以使用相同 UUID；同一用户使用不同 UUID 表示不同结算意图，只要库存充足就允许分别创建。
5. 数据库锁等待超时返回 HTTP 503。客户端继续使用原键重试，不生成新结算意图；超时请求不会留下部分订单或部分冻结库存。
6. 事务组件先写入带幂等键和指纹的完整订单，再在同一事务中执行 ORD-001 的库存条件原子更新并保存订单项。任何一步失败都会一起回滚。
7. 前端持久化请求身份、UUID 和已经取得的订单 ID。网络错误、刷新、HTTP 503 或支付表单失败后复用原键；订单创建成功后只重试支付表单，不再次结算。
8. 只有服务端明确返回订单已经 `CANCELLED` 或 `CLOSED`，前端才放弃旧订单并允许用户发起新结算；普通冲突、网络错误、支付 SDK 错误和 `PAID` 状态不会错误创建新订单。
9. 当前只支持支付宝，但支付方式解析已集中到 `PaymentMethod` 与 `PaymentMethodResolver`；本批次没有接入第二种支付渠道。

## 数据库迁移

Flyway V7 为 `orders` 增加：

- `idempotency_key CHAR(36)`，使用 ASCII 且区分大小写；
- `request_fingerprint CHAR(64)`；
- `(user_id, idempotency_key)` 唯一约束；
- 两列必须同时为空或同时非空的检查约束。

历史 V1～V6 订单允许两列都为空，因此迁移不会为旧订单伪造键或改写业务状态。本机 `Tomato` 和 `tomatomall_demo` 均已迁移到 V7，并通过严格预检确认字段、字符排序规则、唯一索引名称与字段顺序、检查约束名称与表达式、失败迁移记录和字段配对数据均正确。

## 并发与多实例设计

幂等的最终判断由 MySQL 唯一约束完成，而不是前端按钮禁用、Java 进程内 Map 或 Redis 分布式锁。

- 第一个事务提交后，等待相同唯一键的请求读取并返回同一订单。
- 第一个事务回滚后，订单和唯一键一起消失，等待请求可以接管并创建订单。
- 只有命名约束 `uk_orders_user_idempotency_key` 的冲突可以进入重放判断；其他数据库完整性错误不会被伪装成幂等成功。
- MySQL 死锁和锁等待超时按实际错误码或 SQLState 分类，并保留可使用同一键重试的语义。

两个独立后端容器连接同一 MySQL 和 Redis 的实际验收中，两个并发请求最终只创建一张订单、一条订单项并冻结一次库存，其中一个响应带重放标记。该结果证明正确性不依赖单个后端进程，但不是生产吞吐量或集群容量测试。

## 独立审查与修复

未参与实现的独立审查重点检查了跨进程并发、失败接管、迁移精确性、CORS、前端重试和验收脚本安全。审查推动修复了以下问题：

- CORS 现在允许浏览器发送 `Idempotency-Key` 并读取 `Idempotent-Replay`。
- 支付表单以业务码 410 区分已经取消或关闭的订单，前端只在这个明确条件下放弃旧订单。
- V7 预检从“约束大致存在”收紧为精确核对名称、字段顺序、唯一性、启用状态和表达式。
- 双实例脚本不再使用固定容器名称，也不会按名称删除可能属于用户的既有容器。
- 死锁分类的错误码和 SQLState 两个分支分别有测试；预先存在的 `CLOSED` 订单支付行为有直接测试。

修复后的最终独立复核未发现剩余 P0～P3。这里的 P0～P3 表示从严重数据破坏、主要功能阻塞，到重要正确性问题和低风险文档/测试缺口的审查等级。
