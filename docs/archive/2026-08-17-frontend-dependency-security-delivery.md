# SEC-014A 前端生产依赖兼容安全升级交付记录

## 交付目标

旧锁文件的浏览器生产依赖命中 1 个严重、5 个高危和 4 个中危安全告警。本批次在不跨主要版本、不执行 `npm audit fix --force`、不改变后端接口或业务规则的前提下，升级能够兼容修复的依赖，并以自动化测试、生产构建和真实浏览器回归检查兼容性。

本批次只把严重和高危生产告警作为阻止交付的门槛。中危告警仍必须显示和记录；需要跨主要版本的 ECharts/Vue ECharts 升级由 SEC-014B 继续跟踪。测试、开发服务器和构建工具依赖不进入浏览器生产包，但完整依赖树的风险不能隐瞒，由 SEC-014C 独立处理。

## 已完成的依赖升级

- Axios：1.8.4 → 1.19.0；间接依赖 `form-data` 更新为 4.0.6，`follow-redirects` 更新为 1.16.0。
- Element Plus：2.9.7 → 2.14.4；间接依赖 Lodash/Lodash ES 更新为 4.18.1。
- Vue：3.5.13 → 3.5.41。
- Vite：5.4.15 → 5.4.21；依赖树中的 PostCSS 更新为 8.5.26、Nanoid 更新为 3.3.18。
- 新增 `npm run audit:prod`，实际命令为 `npm audit --omit=dev --audit-level=high`。严重和高危使命令失败，中危和低危继续输出但不阻止本批次交付。

所有升级保持原有主要版本，没有使用 `overrides` 强制拼接不满足父依赖契约的版本。`package-lock.json` 记录本次验证的完整依赖树；带下载地址的条目来自 npm 官方注册表并保留完整性校验值。

## 兼容修复与 TDD

依赖升级后，TypeScript 构建首先发现 Element Plus 2.14.4 的消息选项类型不再接受 `ElMessage.center`。登录、注册和商品列表共六处调用删除该选项，消息内容、成功/失败类型和业务流程保持不变。

真实浏览器随后发现两类弃用警告：购物车复选框仍把 `label` 同时作为选中值，商品创建和修改页仍使用文本按钮的 `type="text"` 写法。两项均先增加能在旧源码上失败的 Vitest 契约测试，再分别改为 `value` 和 `link`。这些源码测试只保护本项目采用的接口写法；组件运行兼容性由生产构建和真实浏览器回归补充，不把字符串检查包装成完整组件测试。

Axios 测试使用项目真实共享实例、请求/响应拦截器和替换后的 adapter，验证：

- Cookie 凭据配置仍开启；
- 兼容的 `token` 请求头仍会从会话存储加入请求；
- 网络错误仍把原始 Axios 错误交给调用方处理；
- 控制台只记录错误名称和错误码，不重新输出请求凭据、响应正文或原始敏感错误消息。

- 运行环境：Node.js 20.20.2、npm 10.8.2。
- `npm ci`：从锁文件重新安装成功。
- `npm test`：4 个测试文件，11/11 通过。
- `npm run check:sensitive-logging`：5/5 通过。
- `npm run build`：TypeScript 检查和 Vite 生产构建通过。
- `npm run audit:prod`：退出码 0；严重 0、高危 0，剩余 ECharts/Vue ECharts 两个中危。
- 完整 `npm audit`：1 个严重、5 个高危、6 个中危；这些是开发与构建工具链和上述两个图表生产依赖的合计，不得写成已经清零。
- `npm ls`：退出码 0，当前安装树与锁文件一致，Vue、Vite、Element Plus 和插件的依赖范围满足。
- `git diff --check`：通过，仅有 Windows 行尾转换提示，没有空白错误。

生产构建仍报告缺失背景图片、CSS 使用 `//` 注释和大文件包警告。这些是既有 FE-001，不是依赖升级新增，也没有通过调高阈值或隐藏日志掩盖。

## 真实浏览器回归

本机前端通过 5174 端口访问，后端通过 9001 端口连接本机演示 MySQL/Redis。普通用户回归覆盖：

- 注册、登录、账户读取和退出；
- 300 本商品列表、关键词搜索和商品详情；
- 商品列表加入购物车、购物车数量从 1 调整为 2、复选框和订单确认；
- 创建一张本地待支付订单，并使用原结算标识重试；数据库仍只有一张订单，冻结库存没有重复增加；
- 两次支付表单均进入支付宝官方沙箱收银台，并显示同一订单号和金额。

本轮没有输入沙箱买家凭据或完成付款，因此上述证据只能证明支付表单和跳转兼容，不能写成支付宝付款成功。管理员回归打开了商品详情、库存调整、广告列表、商品创建和广告创建页面，检查表格、表单、下拉框、评分、数量与文件选择组件；没有提交商品、库存、广告或 OSS 变更。

验收结束后，只删除本次创建的临时账户、订单、订单项和购物车记录，并把测试商品库存恢复到操作前的 `amount=43`、`frozen=0`。未删除或改写其他用户数据。

## 验收中发现但未混入本批次的缺陷

- CART-002：商品详情页从路由取得字符串商品 ID，并原样写入购物车 JSON；CART-001 的严格正整数解析会返回 HTTP 400。商品列表使用数字 ID，因此入口正常。
- ACCT-002：注册页把未填写的可选手机号作为空字符串发送；后端仍对空字符串做手机号唯一性查询，导致数据库已有空手机号账户后，新注册被错误提示“电话号码已存在”。
- SEC-015：支付跳转前仍会把 HttpOnly Cookie 对应的令牌复制到浏览器 `localStorage`，需与 PAY-002 的服务端可信返回页一起处理。
- FE-003：只读计算值警告和 Live2D 空渲染对象异常仍能复现；商城主链路可用，但控制台噪声尚未解决。

上述问题均已进入 BACKLOG 和温层计划。本批次没有放宽后端输入检查、重写账户逻辑、修改支付信任边界或恢复废弃 AI assistant，以免把安全依赖升级扩展成难以审查的大改动。

功能提交 `76ac9d0b` 已推送到 `codex/frontend-dependency-security`，并通过 [Pull Request #27](https://github.com/araragi-koyomin/404NotPure/pull/27) 以 squash 方式合并到个人 `master`；合并提交为 `00d71b055b5eddb897ac3c8cb95aefa7fb5b1039`。GitHub 没有为该分支配置远端自动检查，本次合并依据是上述本地测试、在线 npm 审计、真实浏览器回归和独立审查，不能写成远端 CI 已通过。

## 仍需诚实说明的边界

1. ECharts 5 和 Vue ECharts 6 的两个生产中危告警仍存在，安全版本需要跨主要版本，由 SEC-014B 处理。
2. 包含 Vitest、Vite、Rollup 和文件匹配工具的完整开发依赖树仍有严重与高危告警，由 SEC-014C 处理。
3. 项目尚未建立远端 CI；本次命令均在固定本机环境执行。
4. 浏览器回归不是自动化端到端测试套件。Element Plus 的页面运行兼容仍依赖人工浏览器验收，后续升级需要重新执行。
5. 本批次没有证明支付宝沙箱付款成功、真实异步通知或生产部署能力。
