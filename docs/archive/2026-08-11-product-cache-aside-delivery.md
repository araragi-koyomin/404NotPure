# 商品详情 Cache-Aside 与真实 Redis 测试交付记录

## 交付结果

CACHE-001 与 TEST-001 已于 2026-08-11 通过 [Pull Request #7](https://github.com/araragi-koyomin/404NotPure/pull/7) 以 squash 方式合并到个人 Fork 的 `master`，合并提交为 `acff6078`。

本次交付把原有“广告创建或更新时提前缓存关联商品”的设计扩展为通用商品详情 Cache-Aside，并保留广告热门商品预热。它没有修改前端接口、商品响应结构、库存扣减方案、支付宝、OSS 或已废弃的 AI assistant。

## 关键实现

- 商品详情统一使用 `product:detail:v1:{productId}`，由 `ProductDetailCache` 集中生成，商品和广告服务不再分别手写缓存 key。
- 请求先读 Redis；命中 `ProductDTO` 时直接返回，未命中时读取 MySQL 的商品、规格和详情图，回填后返回。
- 正常商品 TTL 随机 1800～3599 秒，用于分散正常过期时间；数据库确认不存在时缓存 `MissingProductCacheEntry`，TTL 随机 60～119 秒，减少同一无效商品 ID 的重复查库。
- 商品创建在事务提交后清除同 ID 的短期不存在标记；商品更新、删除和广告换品只在数据库事务提交后失效相关缓存，数据库回滚时不提前改缓存。
- 缓存未命中和商品更新/删除使用同一 MySQL 商品行悲观写锁，防止较早读取的旧详情在更新已经失效缓存后再次写回。这一锁只用于商品详情缓存正确性，不改变 ORD-001 的库存条件原子更新。
- 广告提交后通过独立新事务重新锁定并读取最新商品再预热，不使用广告事务中较早捕获的 DTO。
- 缓存值类型错误时删除并回查数据库；Redis 读写或删除异常时记录不含 key、缓存值和连接配置的固定警告，并让正确的 MySQL 主链路继续执行。
- 使用 `RedisTemplate<String, Object>`，并关闭项目未使用的 Spring Data Redis Repository 扫描；JPA Repository 继续正常加载。

## TDD 与独立审查

Red 阶段首先运行真实集成测试，8 项出现 1 个失败和 7 个错误，具体证明旧实现不会在未命中时回填、商品不存在会因 `Optional.get()` 抛出错误异常，以及商品规格/详情图在数据库会话关闭后转换会触发延迟加载错误。缓存组件测试在组件尚不存在时产生 19 个编译错误；损坏缓存测试随后证明旧实现只回退数据库、不会删除无法反序列化的值。

首轮冷启动独立审查发现并推动修复：

- 较早的商品读取可能在更新提交并删除缓存后重新写入旧详情；
- 广告提交后的预热可能把事务中捕获的旧商品快照写回；
- 商品创建后没有清除相同 ID 的短期不存在标记；
- 默认测试数量误把三个历史外部探针报告计入；
- 不存在标记命中、随机 TTL 和广告事务回滚测试证据不够直接。

修复后新的独立复核没有发现 P0～P2 问题。复核指出的两个非阻塞问题也已处理：文档明确不存在行并发依赖 MySQL 8 默认 `REPEATABLE READ` 的间隙锁行为；三个并发测试增加写线程已开始执行的信号，避免只靠休眠猜测并发顺序。

## 诚实边界与后续计划

本次测试证明的是功能、事务回滚和特定并发顺序，不是性能容量：

- 没有测量每秒请求数、平均/P95/P99 延迟、缓存命中率或 MySQL 查询量下降，因此不能声称达到特定高并发能力或性能提升百分比；
- 当前行锁避免旧值覆盖，但热门商品 key 过期时，多个请求仍可能排队并重复查库，尚未实现严格的同一商品单次回填；
- 短期不存在标记能降低同一无效 ID 的重复查库，不能直接阻止每次都更换随机 ID 的恶意请求；
- 随机 TTL 能分散正常过期，不能解决 Redis 重启、数据全部丢失或全量冷启动；
- Cache-Aside 不是 MySQL 与 Redis 强一致事务。如果数据库提交后的 Redis 删除失败，旧值可能继续存在到原 TTL；
- 不存在商品与相同 ID 创建的协调依赖当前 MySQL 8 `REPEATABLE READ` 行为，改变隔离级别或数据库后必须重测。

[Redis 缓存性能验证与热点保护计划](../plans/cache-performance.md) 已登记 PERF-001 与 CACHE-002。顺序是先完成 DATA-001，再用固定数据和参数压测当前实现；只有测量证明热点过期确实造成明显重复回源或连接池等待时，才增加单次回填保护并按相同参数复测。
