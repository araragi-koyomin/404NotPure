# 本机与面试演示数据计划

## 背景与目标

当前本机数据库结构可由 Flyway 建立，但没有可供浏览器演示的书籍数据。DATA-001 提供一套进入 Git、可以重新执行且不会清空数据库的确定性生成器，让商品列表、详情、库存、广告和本地演示登录在面试环境中可稳定复现，同时为后续分页和性能测试提供固定规模数据。

演示数据不是自动化测试夹具。CACHE-001/TEST-001 的真实 MySQL/Redis 测试必须自行创建带随机标识的少量商品和缓存 key，并在结束后只清理自己创建的数据；测试不得依赖 DATA-001，也不得执行 Redis `FLUSHDB`。

## 已确认范围

- 默认生成 300 本书，数量通过参数调整，固定 seed 时元数据和资源路径保持一致；
- 约 20 本使用公版经典书籍的书名、作者等事实信息，商品简介由项目重新编写；其余书籍使用小型词库和模板确定性生成，不伪装成真实出版物；
- 每本书具有价格、评分、现有前端支持的分类、可用库存，冻结库存初始为 0；
- 每本书具有作者、出版社、装帧等 3～5 个规格和 1～2 张详情图；
- 封面、详情图和广告图由程序生成 SVG 到前端 `public` 下的忽略目录，不依赖 OSS Bucket 或第三方图片链接，也不提交几百个生成产物；
- 默认生成 5～8 个广告，关联固定的热门书籍；
- 默认生成 500 个普通规模用户，以及 1 个演示管理员 `demo_admin` 和 1 个演示普通用户 `demo_user`；批量用户使用 `load_user_0001` 等保留命名空间；
- 所有用户密码只从运行时 `TOMATOMALL_DEMO_PASSWORD` 读取，使用现有 BCrypt 编码器保存，不在仓库、日志或报告中保存密码值；
- 不创建购物车、评论、订单或支付记录，不能把生成用户包装成真实业务用户。

## 导入与安全边界

- 只允许写入名称严格等于 `tomatomall_demo` 的独立数据库。数据库由使用者显式创建，导入器不创建、删除或重建数据库；
- `scripts/demo-data/import-demo-data.ps1` 是单一人工入口，调用 Java/Spring 导入器；不随普通应用启动、Flyway 正式迁移或默认 Maven 测试自动导入；
- 脚本不得包含 `DROP DATABASE`、`DROP TABLE`、`TRUNCATE` 或无条件全表 `DELETE`，不得清空现有数据库；
- 导入器使用 MySQL 命名锁防止两个进程同时导入，并通过保留的图片路径、广告路径和用户名识别自己的记录；
- 重复执行时不得重复插入同一批演示商品、库存、规格、广告或用户，也不得覆盖用户后来修改的密码、资料或库存；
- 导入使用数据库事务，任一步失败时不得留下只有商品没有库存、规格或广告的半套数据；
- 只能识别和管理 DATA-001 自己声明的演示记录，不得删除或覆盖后来通过页面创建的数据；
- 不包含账户密码、数据库密码、OSS AccessKey、支付宝参数、JWT 密钥或其他真实配置；
- 本地图片只保证页面稳定展示，不作为 OSS 集成证据。真实 OSS 继续通过显式生命周期和业务删除权限探针验证，默认测试不访问外部服务。

## 实施前需要核对的结构限制

当前 `products` 表没有独立业务编码或演示数据标记字段，`account.username`/`telephone` 和 `stockpile.product_id` 也没有数据库唯一约束。导入器必须首先校验独立数据库名称，再使用 MySQL 命名锁串行执行；商品通过 DATA-001 专用本地封面路径识别，账户通过保留用户名识别，不能仅凭普通书名或姓名更新记录。发现同一标识对应多行时必须失败并回滚，不能随意选择一行。

DATA-001 不修改正式领域实体、不增加 Flyway 迁移，也不提前夹带 DB-001 的唯一约束。它依靠独立数据库、保留命名空间、精确数量检查和单进程命名锁提供本机导入安全性；这不是生产环境的数据初始化机制。

商品列表当前一次返回全部商品及其规格和图片，前端再执行内存过滤。默认 300 本书会用于暴露这一真实边界，但 DATA-001 不改变现有 API；分页、服务端筛选、关联查询数量和响应体大小由 API-002 单独处理，并应在 PERF-001 前完成。

## 验收标准

1. 目标数据库不是精确的 `tomatomall_demo`、密码环境变量缺失或数量越界时，在任何业务写入前拒绝执行；
2. 在 Flyway 已建立结构的空数据库上显式执行脚本，默认生成 300 本书、500 个规模用户、2 个演示账户、对应库存/规格/图片路径和 5～8 个广告；
3. 对同一数据库再次执行脚本，记录数量不增加、库存不重复、广告关联不漂移，既有密码、资料和被业务修改的库存不被重置；
4. 在数据库已有非 DATA-001 商品和账户时执行脚本，这些记录及其库存保持不变；
5. 人工制造批量写入中途失败时，数据库不留下半套演示数据；
6. 相同 seed 和数量产生相同的书籍元数据、用户名和图片路径；不同 seed 能产生另一批虚构字段但仍保留公版核心书目；
7. 前端商品列表、详情和广告能够显示程序生成的本地 SVG，演示账户可以登录，库存接口返回预期数量；
8. 导入说明不读取或输出真实 `.env` 值，默认 Maven 测试不会触发导入器；
9. 文档、脚本和生成器通过格式检查，真实数据库验证记录进入冷层后才能从 BACKLOG 移除 DATA-001。

## 当前实施进度

- 已完成确定性 Java 生成器、批量 JDBC 导入器、MySQL 命名锁、单事务回滚、数据库名称双重校验、PowerShell 单一入口和本地 SVG 生成器；
- 纯生成测试已证明默认规模为 300 本书、500 个规模用户和 2 个演示账户，并验证固定种子、唯一保留路径、参数保护及不引用第三方图片；
- 真实 MySQL 8 测试已在隔离临时库验证默认 300 本书/502 个账户的首次导入和重复导入，并验证既有密码、资料、库存及非 DATA-001 商品、库存和账户不会被覆盖；
- 真实 MySQL 8 测试已通过故意在商品写入后抛出普通异常和严重错误，验证商品、库存、规格、图片、广告和账户全部回滚；
- 真实 MySQL 8 测试已验证两个导入器同时启动时由命名锁串行执行，也验证大小写或尾空格不同的保留用户名/资源路径不会绕过重复识别，已有等价重复标识会拒绝并回滚；
- 商品分类已按前端现有契约保存为 13 个英文代码，本地 SVG 再将代码转换为中文显示；最终默认 Maven 回归为 30 个测试类、187 项测试全部通过，且没有运行真实 OSS 或支付宝探针；
- 已从被 Git 忽略的本机 `.env` 静默读取 `TOMATOMALL_DEMO_PASSWORD`，在独立 `tomatomall_demo` 执行两次完整脚本：首次新增 300 本书、300 条库存、1200 条规格、300 张详情图、502 个账户和 6 个广告；第二次所有新增数量均为 0，证明默认演示库重复执行不会制造重复记录；
- 独立 SQL 核对确认 Flyway 版本为 V2，所有商品分类均属于前端支持的 13 个分类代码，冻结库存均为 0，每本书恰好具有 1 条库存、4 条规格和 1 张详情图，没有缺失关联、重复用户名或重复书名；生成目录包含 300 张封面、300 张详情图和 6 张广告图，共 606 个非空 SVG 文件；
- 使用当前分支重新构建后端镜像，并以只绑定本机 `127.0.0.1:18081` 的临时容器连接 `tomatomall_demo`：商品列表返回 300 项，商品详情返回 4 条规格和 1 张详情图，库存可用数量为正且冻结量为 0；`demo_user` 登录成功并收到 HttpOnly Cookie，登录后广告接口返回 6 项；
- Docker Desktop 重启后已使用当前分支重新构建并启动 backend、db、frontend 和 redis 四服务；当前后端容器通过仅对本次命令生效的 `DB_NAME=tomatomall_demo` 覆盖连接演示库，容器启动日志确认 8080 端口和 Spring Boot 正常启动，MySQL 与 Redis 健康检查通过；本机 `.env` 原有日常数据库名没有被改写；
- 前端通过真实商品响应中的路径返回 `image/svg+xml`，浏览器实际显示《傲慢与偏见》中文封面，未发现路径错误、空白或乱码；登录页正常显示且没有浏览器控制台警告或错误，四服务继续保持运行，供项目所有者人工验收；
- 项目所有者已使用保持运行的前端完成页面人工验收，确认演示账户登录、300 本商品列表、《傲慢与偏见》详情、本地封面和详情图片、库存与规格以及 6 个广告均符合预期，并于 2026-08-11 明确确认 DATA-001 质量通过；
- 已在被 Git 忽略的本机 `.env` 中生成并保存随机 `JWT_SECRET`，正常 Compose 启动不再依赖临时注入；演示密码和 JWT 密钥值均未进入 Git、日志或文档；
- 首次脚本验收发现 Exec Maven Plugin 默认等待 MySQL Connector/J 的 JVM 后台清理线程并产生 15 秒警告；DATA-001 配置为不等待该 JVM 级守护线程，导入器自身仍通过 try-with-resources 关闭每一个 JDBC 连接，命令结束时由 JVM 正常终止后台线程，避免把成功导入误报成警告。

当前保留一个不会阻塞本机空演示库导入的低风险边界：如果数据库在导入前已被人工写入一条只在重音符号上不同的详情图片路径或规格名，导入器不会删除该记录，并可能补入标准 DATA-001 子记录。商品、账户和广告主标识已对这类 MySQL 排序规则等价冲突执行拒绝和事务回滚；子记录的完整脏数据规范化不在本轮继续扩大。

## 非目标

- 不把演示数据和生成用户当成生产数据或真实用户增长；
- 不抓取商业网站内容或长期引用第三方图片；
- 不把 OSS、支付宝或公网部署设为导入前置条件；
- 不为方便重置而自动删除 Docker volume、数据库或用户记录；
- 不在本任务中创建订单、支付、购物车、评论或性能基准报告；
- 不在本任务中实现商品分页、服务端搜索或列表查询优化；
- 不宣称导入若干商品即可证明缓存性能提升。
