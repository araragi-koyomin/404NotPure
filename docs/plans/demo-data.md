# 本机与面试演示数据计划

## 背景与目标

当前本机数据库结构可由 Flyway 建立，但没有可供浏览器演示的书籍数据。DATA-001 提供一套进入 Git、可以重新执行且不会清空数据库的演示数据，让商品列表、详情、库存和广告在本机与面试环境中可稳定展示。

演示数据不是自动化测试夹具。CACHE-001/TEST-001 的真实 MySQL/Redis 测试必须自行创建带随机标识的少量商品和缓存 key，并在结束后只清理自己创建的数据；测试不得依赖 DATA-001，也不得执行 Redis `FLUSHDB`。

## 已确认范围

- 约 12～20 本公版经典书籍；书名、作者等事实信息可以使用，商品简介和详情由项目重新编写；
- 每本书具有价格、评分、分类、可用库存，冻结库存初始为 0；
- 每本书具有作者、出版社、装帧等规格；
- 封面和少量详情图作为仓库内本地演示资源维护，不依赖 OSS Bucket 或可能失效的第三方图片链接；
- 3～5 个广告位关联其中的热门书籍；
- 不创建账户、购物车、评论、订单或支付记录。这些数据通过正常注册和业务操作产生，不能伪造成已经发生的交易。

## 导入与安全边界

- 演示数据脚本必须由开发者人工显式执行，不随应用启动、Flyway 正式迁移或默认 Maven 测试自动导入；
- 脚本不得包含 `DROP DATABASE`、`DROP TABLE`、`TRUNCATE` 或无条件全表 `DELETE`，不得清空现有数据库；
- 重复执行时不得重复插入同一批演示商品、库存、规格或广告；
- 导入使用数据库事务，任一步失败时不得留下只有商品没有库存、规格或广告的半套数据；
- 只能识别和管理 DATA-001 自己声明的演示记录，不得删除用户后来创建的商品；
- 不包含账户密码、数据库密码、OSS AccessKey、支付宝参数、JWT 密钥或其他真实配置；
- 本地图片只保证页面稳定展示，不作为 OSS 集成证据。真实 OSS 继续通过显式生命周期和业务删除权限探针验证，默认测试不访问外部服务。

## 实施前需要核对的结构限制

当前 `products` 表没有独立业务编码或演示数据标记字段，且 `stockpile.product_id` 的数据库唯一约束仍由 DB-001 跟踪。实现 DATA-001 时必须选择不会误认用户商品的稳定标识方案，并在重复导入测试中证明库存不会产生第二行。不能仅凭可能与用户商品重名的普通标题执行删除或覆盖。

DATA-001 不应为了标记演示数据擅自修改正式领域实体或提前夹带 DB-001。若无法在不改变 schema 的前提下安全实现可重复导入，必须暂停并与项目所有者确认独立标记表或新迁移方案。

## 验收标准

1. 在 Flyway 已建立结构的空数据库上显式执行脚本，商品、库存、规格、图片路径和广告全部导入成功；
2. 对同一数据库再次执行脚本，记录数量不增加、库存不重复、广告关联不漂移；
3. 在数据库已有用户商品时执行脚本，用户商品及其库存保持不变；
4. 人工制造中途失败时，数据库不留下半套演示数据；
5. 前端商品列表、详情和广告能够显示本地图片，库存接口返回预期数量；
6. 导入说明不要求读取或输出真实 `.env` 值；
7. 文档、脚本和资源通过格式检查，真实数据库验证记录进入冷层后才能从 BACKLOG 移除 DATA-001。

## 非目标

- 不把演示数据当成生产数据；
- 不抓取商业网站内容或长期引用第三方图片；
- 不把 OSS、支付宝或公网部署设为导入前置条件；
- 不为方便重置而自动删除 Docker volume 或用户数据库；
- 不在本任务中创建账户、订单、支付、评论或性能基准数据；
- 不宣称导入若干商品即可证明缓存性能提升。
