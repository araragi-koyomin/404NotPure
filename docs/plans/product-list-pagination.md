# 商品列表分页与服务端查询计划

## 背景与基线

当前 `GET /api/products` 返回完整 `ProductVO` 数组，服务层先读取全部商品，再通过两个延迟关联分别读取规格和详情图。使用 DATA-001 的 300 本演示书籍进行孤立单请求测量，响应体为 242,306 字节，三次请求约为 0.31、0.31 和 0.62 秒，一次请求使 MySQL `Com_select` 增加 601。该结果只表示当前本机单请求基线，不是压力测试或生产容量。

前端 `AllProduct.vue` 一次加载全部商品，在浏览器内按书名和 13 个中文分类过滤并渲染全部卡片。商品列表不使用 Redis 商品详情缓存；API-002 继续保持列表摘要读取 MySQL、点击详情读取现有 Redis Cache-Aside 的职责分离。

## 已确认接口

- 保留旧 `GET /api/products` 及其 `Response<List<ProductVO>>` 数据结构；
- 新增 `GET /api/products/page`，返回 `Response<ProductPageVO>`；
- `ProductPageVO` 包含 `items`、`page`、`size`、`totalElements` 和 `totalPages`；
- `ProductSummaryVO` 只包含 `id`、`title`、`price`、`rate`、`cover`、`category` 和 `author`；
- 页码从 1 开始，默认每页 20 条，最大 100 条，前端提供 20/40/60 条选择；
- 关键词去除首尾空格后同时搜索书名和“作者”规格，空关键词等价于不筛选；
- `categories` 接收逗号分隔的数据库英文代码，中文分类只属于前端显示；
- `sort` 只允许已确认的 `id,asc`、`id,desc`、`rate,desc`、`price,asc`、`price,desc`、`title,asc` 六种组合，默认 `id,asc`；非 ID 排序追加 ID 升序，空值排在正常值之后；
- 无效页码、数量、分类、排序和过长关键词返回 HTTP 400，并保持 `Response<T>` 外层；合法但超过最后一页的请求返回空 `items`。

## 前端行为

- 停止输入关键词 400 毫秒后查询，按回车立即查询，清空后立即查询；
- 旧请求晚于新请求返回时必须丢弃旧结果；
- 修改关键词、分类、排序或每页数量后回到第一页；
- 主动页码、分类、排序和数量变化写入浏览器历史，连续输入关键词只替换当前历史；
- 刷新、复制 URL 和从详情页返回时恢复查询状态；
- 商品卡片显示两位小数价格，客户端价格只用于展示；
- 明确显示加载中、空结果和普通中文错误，不输出敏感响应正文。

项目所有者选择不引入 Vitest、Vue Test Utils 或 Playwright。因此前端通过 `npm run build`、现有敏感日志检查和真实浏览器场景验收；搜索等待、旧请求竞争和 URL 恢复没有组件级自动回归保护，该限制必须保留在交付报告中。

## TDD 顺序

1. 失败测试固定默认分页、第二页、总数和越界页行为；
2. 失败测试固定书名搜索、作者搜索、空关键词和作者缺失；
3. 失败测试固定单分类、组合分类、未知分类拒绝；
4. 失败测试固定白名单排序、同值 ID 次序和无效参数 HTTP 400；
5. 失败测试证明旧全量接口结构不变、新分页接口为公开 GET；
6. 真实 MySQL 失败测试证明当前页增加商品时查询数量不能线性增长；
7. 实现最小后端功能并保持上述测试通过；
8. 迁移前端，再执行构建、敏感日志检查和浏览器验收；
9. 使用相同 300 本数据记录改造后响应大小、查询次数和单请求耗时；
10. 完整 Maven 回归、独立审查、问题修复和针对性复核。

真实 MySQL 测试必须创建带随机标识的隔离商品和规格，只清理自己的记录，不依赖 DATA-001，也不清空数据库或 Redis。

## 当前实现与验证状态

- Red 阶段：新增接口尚未实现时，4 个首批测试中 3 个按预期失败；`/api/products/page` 被旧 `/{id}` 路由当成 ID，正常分页与作者搜索返回 400，非法页码也没有统一 `Response` 错误体；旧 `GET /api/products` 数组兼容测试通过。
- Green 阶段：新增独立分页查询仓库，以总数查询、当前页摘要查询、当前页作者批量查询完成返回；作者取同一商品最低规格 ID，空作者返回 `null`；非 ID 排序在字段排序后追加 ID 升序，正常值排在空值前。
- 真实 MySQL 针对性测试为 11/11，覆盖默认/第二页/极端越界页、书名与作者关键词、Unicode 全角空格、组合分类、空作者、多作者、六种排序、排序稳定性、评分与价格空值顺序、无效参数、旧完整接口结构兼容，以及每页 1 本和 20 本时均固定为三条查询。
- Hibernate 统计证明当前页包含 20 本商品时为 3 条 SQL；同一次测试运行中的旧接口仍对 300 本演示数据执行 601 条 SQL。这里证明的是查询次数不会随当前页商品数线性增长，不代表已完成压力测试。
- 完整 Maven 回归为 31 个测试类、198/198；`npm run build` 和 `npm run check:sensitive-logging` 通过。前端构建继续报告既有 FE-001 背景资源、CSS 注释和大包警告。
- Docker Desktop 在更新容器时发生内部镜像数据块 `input/output error`；普通重启后引擎停在 `stopped`，通过 `docker desktop stop --force` 只结束失效桌面进程、再正常启动后恢复。MySQL/Redis 命名数据卷未删除，恢复后四服务运行，Redis 返回 `PONG`，演示库仍为 300 本商品。
- 新分页接口在 300 本数据上的第一页响应为 4,388 字节，三次孤立 HTTP 请求约为 0.0222、0.0208 和 0.0216 秒；旧接口基线为 242,306 字节和约 0.31、0.31、0.62 秒。响应体约减少 98.2%，这里只能说明本机单请求传输和查询工作显著减少，不能外推为压力测试吞吐量。
- 默认按 ID 分页的 MySQL 查询计划使用主键索引并只扫描当前页附近记录；关键词查询仍扫描 300 行商品，并通过既有 `product_id` 索引检查作者规格。当前数据量和单请求时间没有给出新增索引的必要证据，因此 API-002 不增加 Flyway 迁移；正式搜索压力和索引取舍由 PERF-001 测量。
- HTTP 自动验收确认前两页各 20 本且没有重复 ID、文学分类返回项全部为 `literature`、价格升序有效、非法页码为 HTTP 400、前端服务为 HTTP 200。应用内浏览器曾因本机 URL 安全策略拒绝交互；改用项目所有者明确指定的 Chrome 插件后，本机真实页面完成自动验收：第一页和第二页各 20 本且无重复，价格升序、文学分类 36 本、400 毫秒搜索的最后输入生效、按回车立即搜索、键盘清空搜索、每页 20/40 切换、详情返回，以及浏览器前进/后退均保持 URL 和页面状态一致。
- Chrome 验收创建了一个不含真实个人信息、没有管理员权限的本机演示账户，没有添加购物车或订单数据。浏览器前进时出现一次 Vue “尝试写入只读计算值”警告，但 URL、筛选、排序和结果正确恢复；该无可见功能影响的运行时告警由 FE-003 单独跟踪，不把它误写成 API-002 已解决的问题。废弃助手的 Live2D 渲染错误仍不属于本轮维护范围。
- 最终独立复核发现常规浏览器验收没有覆盖“输入关键词后不满 400 毫秒立即后退”的顺序：旧搜索计时器可能在路由已经恢复后执行，并用 `page=1` 覆盖恢复的页码。代码现已在处理外部路由状态前取消待执行搜索，前端构建和敏感日志检查通过，针对性只读复核确认原 P2 已修复且没有剩余 P0～P2。新的 Chrome 会话建立第 1、2、3 页历史，在第 3 页输入关键词后立即后退；等待超过 400 毫秒后，URL、空搜索框、300 本总数和分页控件仍保持第 2 页，浏览器前进后同样恢复第 3 页，最终行为证据通过。

## 非目标与风险

- 不给分页查询组合增加 Redis 缓存，不逐个读取商品详情缓存；
- 不修改商品详情、库存、购物车、订单、支付宝、OSS 或已废弃 AI assistant；
- 不删除旧全量列表接口，不大规模重写前端；
- 不在本任务中执行正式压力测试或声称达到特定并发能力；
- 不在没有查询计划和测量证据时增加数据库索引。若证据要求新索引，暂停并讨论独立 Flyway 迁移；
- 前端缺少组件测试是已接受的回归风险，不能用只检查源码字符串的弱测试掩盖。
